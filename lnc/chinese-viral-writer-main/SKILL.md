## 关键概念区分

### content-filter vs content-eval

这两个 skill 容易混淆，但用途完全不同：

| 维度 | `content-filter/` | `content-eval`（需独立安装） |
|------|-------------------|-----------------|
| **用途** | 筛选对标文章是否值得改写 | 评估自己写的文章质量 |
| **时机** | 素材重构模式**开始前** | 草稿完成**后** |
| **输入** | 别人的文章（对标素材） | 自己的文章（草稿） |
| **输出** | A/B/C 分类 + 平台适配建议 | 多维度评分 + 改进建议 |
| **决策** | 是否继续改写 | 是否需要修改 |

**使用场景：**

```
对标文章 → content-filter/ → 值得改写？
                              ↓ 是
                         提取核心原理
                              ↓
                         生成草稿
                              ↓
                    草稿 → /content-eval → 评分 ≥ 9.0？
                                           ↓ 是
                                        定稿发布
```

**常见错误：**
- ❌ 用 content-filter 评估自己的草稿
- ❌ 用 content-eval 筛选对标文章
- ❌ 跳过 content-filter 直接改写（可能浪费时间在 C 类文章上）

## 哲学维度：认知劫持层

创作底层逻辑源自八位哲学家。**这不是装饰，而是捕获注意力的核武器。**

详见 `references/philosophy-weapons.md`

### 八大认知劫持机制

| 哲学家         | 机制             | 核心作用                           | 应用时机           |
| -------------- | ---------------- | ---------------------------------- | ------------------ |
| **胡塞尔**     | 意向性           | 精准定位唤起读者注意力的「某物」   | 标题、开头第一句   |
| **海德格尔**   | 上手状态         | 让阅读成为无意识的、流畅的体验     | 全文节奏、句式设计 |
| **尼采**       | 权力意志         | 激发优越感或反驳冲动               | 情绪扳机、断言金句 |
| **福柯**       | 话语权力         | 用你的叙事框架替换读者的思维框架   | 论证结构、概念命名 |
| **列维纳斯**   | 他者的面容       | 让读者产生「这就是我」的瞬间认同   | 众生相设计         |
| **维特根斯坦** | 语言游戏         | 同一思想可用无限种语言方式重新表达 | 素材重构、金句转译 |
| **斯多葛**     | 控制二分法       | 将焦虑从不可控转移到可控           | 解决方案、金句结尾 |
| **荣格**       | 原型与集体无意识 | 激活读者内心深处的原型叙事         | 人物塑造、叙事结构 |

### 应用公式

**开头（胡塞尔 + 尼采）：**

```
[一个具体的、唤起注意力的「某物」] + [一个激发优越感或愤怒的断言]
```

**正文（海德格尔 + 列维纳斯 + 福柯）：**

```
[无意识流畅的阅读体验] + [让读者看到自己的镜像] + [用你的框架定义问题]
```

**结尾（尼采 + 维特根斯坦）：**

```
[权力意志的断言] + [留下可被重新表达的思想种子]
```

## 论证兵法：正向与逆向齐上

详见 `references/argumentation.md`

**核心理念：** 断言没有论证是空洞的，论证只有正向是单薄的。

### 双向论证结构

| 论证类型     | 核心问题                   | 效果       |
| ------------ | -------------------------- | ---------- |
| **正向论证** | 为什么我是对的？           | 建立信任   |
| **反驳误解** | 为什么常见观点是错的？     | 破除惯性   |
| **拆解替代** | 为什么其他方案不行？       | 排除干扰   |
| **划定边界** | 我的观点在哪些情况下成立？ | 增强可信度 |

### 交替共振模式

```
[正向论点] → [可能的反驳] → [回应反驳]
     ↓
[正向论点 2] → [可能的反驳] → [回应反驳]
     ↓
[综合结论：无懈可击]
```

## 内容地图：多维内容构建

详见 `references/content-map.md`

**核心理念：** 单篇文章是点，内容地图是面。「让人进去就不想出来」的本质是创建内容引力场。

### 四个维度

| 维度         | 核心问题                   | 目的               |
| ------------ | -------------------------- | ------------------ |
| **深度递进** | 入门/进阶/深度版本是什么？ | 服务不同程度的读者 |
| **角度互补** | 正面/反面/另类角度是什么？ | 满足不同立场的读者 |
| **形式多样** | 长文/短文/清单版本是什么？ | 适应不同消费场景   |
| **情绪交替** | 最近内容的情绪分布平衡吗？ | 避免读者疲劳       |

### 连接策略

1. **问题延展**：每篇文章解决一个问题，同时引出新问题
2. **概念嵌套**：创建独有概念体系，形成概念网络
3. **系列标记**：明确的系列命名，让读者知道这是一个系列
4. **互相引用**：在文章中自然引用其他文章，形成网状结构

### 配图位置判断原则

**核心问题：这个地方加张图，能帮助理解还是纯粹凑数？**

| 判断维度 | 需要配图                     | 不需要配图     |
| -------- | ---------------------------- | -------------- |
| 补充信息 | 文字难以描述的场景、数据关系 | 文字已经很直观 |
| 具象概念 | 抽象概念需要可视化           | 概念本身易懂   |
| 引导想象 | 情节转折、氛围渲染           | 情感叙述已充分 |
| 结构标识 | 章节过渡、重点强调           | 段落连贯无断点 |

**配图服务于内容，避免：**

- 重复文章中已经很直观的信息
- 为凑数而配的装饰性图片
- 与内容无关的通用图片

### 图片标题要求

**每张图片（除封面图外）必须有描述性标题，禁止使用：**

- `插图1`、`插图2`
- `章节一`、`章节二`
- `图片`、`配图`

**正确示例：**

```markdown
![程序员在深夜独自面对屏幕的孤独身影](./_attachments/section-01.png)
![AI 与人类能力对比的演化曲线](./_attachments/section-02.png)
```

## 写作铁律

详见 `references/style-rules.md`

**必须做到：**

- 第一人称「我」叙事
- 口语化，像和朋友深夜聊天
- 跳跃式思维，忘掉「首先、其次」
- 短句为主，几句话就分段
- 多用设问引导

**绝对禁止：**

- 破折号（——）、冒号（：）、双引号（""）
- 「首先」「其次」「此外」「总而言之」
- 连续三句以上排比句
- 任何 Emoji
- 学术腔、说教腔

**排版规范：**

- 段落之间空一行
- 一段 3-5 行以内
- 中英文/中文数字之间加空格
- 使用直角引号「」

### 三层防线去 AI 味

**去 AI 味不是靠提示词，升维才是上上策。**

| 防线层次     | 策略                     | 检验标准                    |
| ------------ | ------------------------ | --------------------------- |
| **表层防线** | 格式词汇规范（禁止列表） | 不含禁止词、格式规范        |
| **中层防线** | 具体细节 + 个人经历      | 有「只有我才能写出」的细节  |
| **深层防线** | 跨学科视角升维           | AI 无法生成同样的跨学科连接 |

**深层防线自检问题：**

1. 这篇文章是否挂靠了某个学科的视角？
2. 跨学科的连接是否自然、有洞察？
3. 把主题给 AI，它会做出同样的融合吗？

如果 AI 能轻易做出同样的融合（如「时间管理 + 二八法则」），那不叫升维。真正的升维是意想不到的、需要深度理解才能建立的连接。

### 原创模式流程

**前置条件：** 品牌配置已在「第零步」确定。以下所有步骤都应遵循当前品牌配置（如有）的调性、语言风格和内容边界。

**第一步：战略输出**

收到主题后，先输出战略方案（**六轨并行：选题验证 + 张力共鸣法 + 哲学武器库 + 跨学科升维 + 论证兵法 + 内容地图定位**）。如有品牌配置，战略输出应符合品牌调性：

**〇. 选题交集验证**（详见 `references/creator-mindset.md`）

在展开战略方案前，先验证选题质量：

```
好选题 = 你的专业领域 ∩ 读者的普遍兴趣 ∩ 当下的时间节点
```

| 要素         | 自检问题                                   | 不合格信号         |
| ------------ | ------------------------------------------ | ------------------ |
| **专业领域** | 我对这个话题的研究深度超过 90% 的读者吗？  | 需要边查边写、心虚 |
| **读者兴趣** | 这个话题触及读者的哪个需求层次（马斯洛）？ | 只有小众群体关心   |
| **时间节点** | 为什么是现在写？有什么时效性钩子？         | 什么时候写都一样   |

**选题不合格处理：**

- 只满足 1 项 → 建议更换选题或调整角度
- 满足 2 项 → 可继续，但需强化弱项
- 满足 3 项 → 理想选题，继续战略展开

**创作者心法自检：**

- [ ] 这个选题符合我的价值观吗？（不符合就不写）
- [ ] 我能写出「只有我才能写」的内容吗？（活人感检验）
- [ ] 我愿意为这篇文章的每一个字负责吗？（真诚检验）

---

**A. 张力共鸣法四步骤**

1. **张力场**：`[宏大叙事] vs. [个体真实]` 的具体对立
2. **众生相轮廓**：3-5 个具体人物画像（群体 + 场景 + 行为）
3. **情绪扳机**：`[总结性概括] + [带情绪的断言]`
4. **时效性嫁接**：植入的热点词汇或事件

**B. 哲学武器库部署** 5. **意向性锚点**（胡塞尔）：开头用什么「某物」唤起注意力？6. **权力意志激发**（尼采）：用什么断言激发优越感或反驳冲动？7. **框架劫持策略**（福柯）：用什么概念/命名替换读者的思维框架？8. **镜像设计**（列维纳斯）：众生相中哪个最能让读者看到自己？

**C. 跨学科升维**（去 AI 味的核心策略）9. **学科挂靠**：选择一个学科视角来「升维」这个主题

- 可选：心理学 / 传播学 / 新闻学 / 商科 / 艺术
- 示例：用心理学的「认知失调」来解释程序员焦虑

10. **跨学科连接**：这个学科视角如何与主题产生独特的洞察？

- 检验：AI 能轻易做出同样的连接吗？如果能，换一个角度

**D. 论证兵法**（正向与逆向齐上）11. **正向论证**：为什么我的观点是对的？（核心证据和逻辑链）12. **逆向论证**：

- 常见误解是什么？为什么是错的？
- 替代方案是什么？为什么不行？
- 我的观点的边界条件是什么？

**E. 内容地图定位** 13. **深度定位**：这篇文章是入门 / 进阶 / 深度 / 实战 / 反思？14. **角度定位**：这篇文章是正面 / 反面 / 中立 / 另类角度？15. **情绪定位**：这篇文章是激励 / 共鸣 / 挑战 / 反思基调？16. **关联文章**：这篇文章和哪些已有/计划中的文章形成关联？

**F. 结构方案** 17. **章节结构判断**：

- 需要分章节 / 无需分章节
- 若需分章节：列出 3-6 个章节标题草案
- 若无需分章节：说明将用自然段落 + 金句组织

等待用户确认。

**第二步：执行创作**

确认后，完成 800-1500 字文章草稿。

**第三步：内容评估循环**

草稿完成后，自动进入评估-改写循环：

1. **调用评估**：使用 `content-eval`（需独立安装） skill 对草稿进行多维度评估
   - 如未安装 `content-eval`（需独立安装），提示用户安装：https://github.com/iamzifei/chinese-viral-editor
   - **使用当前品牌配置**：如有品牌配置，传入配置名称进行品牌一致性评估
   - 评估维度包括：张力场强度、情绪扳机效果、众生相穿透力、金句质量、品牌一致性（如有配置）

2. **根据评分决策**：
   | 综合评分 | 改写次数 | 操作 |
   |---------|---------|------|
   | ≥ 9.0 | - | ✓ 通知用户确认，进入下一步 |
   | < 9.0 | < 3 | → 根据评估反馈改写，返回评估 |
   | < 9.0 | ≥ 3 | ⚠ 通知用户进行人工评估和干预，用户确认后进入下一步 |

3. **改写策略**：根据评估输出的具体建议，针对性改进：
   - 开头吸引力不足 → 重新设计胡塞尔意向性锚点
   - 张力场不够尖锐 → 加强对立面的冲突
   - 众生相不够真实 → 增加具体场景细节
   - 金句力度不够 → 重新设计尼采式断言

4. **HKR 自检**（详见 `references/creator-mindset.md`）：
   在调用 `content-eval`（需独立安装） 前，先进行 HKR 三维度快速自检：
   | 维度 | 核心问题 | 理想读者反应 |
   |-----|---------|-------------|
   | **H (Hook)** | 开头能勾住人吗？ | 「卧槽，还有这种事？」 |
   | **K (Knowledge)** | 读完能学到新东西吗？ | 「原来是这样，学到了」 |
   | **R (Resonance)** | 能让读者感到被理解吗？ | 「对对对，我也是这么想的」 |
   - 三者兼备 → 优秀，可提交评估
   - 至少两样 → 及格，可提交但需关注弱项
   - 只占一样 → 先自行改进再提交
   - 一样都没 → 重新审视战略方案

5. **评估结果归档**：将每次评估的分数和反馈保存，用于 RLHF 学习

**第四步：RLHF 学习**

用户确认草稿后，将评估反馈纳入 RLHF 自进化系统：

- 记录本次应用的规则及评估分数
- 高分规则得到强化
- 低分规则被标记观察
- 触发规则整合检查（每 10 次）

**第五步：确定章节结构**

用户确认草稿后，根据文章内容智能判断是否需要分章节：

| 条件                           | 结构选择   | 说明                         |
| ------------------------------ | ---------- | ---------------------------- |
| 字数 ≤ 1000 且 核心观点 ≤ 2 个 | **无章节** | 用自然段落 + 加粗金句组织    |
| 字数 > 1000 或 核心观点 ≥ 3 个 | **有章节** | 使用 `## 一、二、三...` 标题 |

**无章节结构示例：**

- 自然段落流畅过渡
- 用加粗（`**金句**`）突出核心观点
- 段落之间用空行分隔
- 情绪递进自然，一气呵成

**有章节结构规范：**

1. **章节数量**：3-6 个章节，每个章节代表一个独立观点或论述角度
2. **标题格式**：`## 一、标题` `## 二、标题` ... 或 `## 尾声`
3. **标题撰写原则**：
   - 简洁有力，5-12 个字
   - 用断言式或疑问式，禁止「关于 xxx」「浅谈 xxx」
   - 体现章节核心张力或观点
   - 相邻标题之间有递进或对比关系
4. **章节内容**：每章节 150-300 字，有独立的小高潮
5. **章节间过渡**：自然衔接，可用设问引出下一章节

**章节标题示例：**

```
## 一、程序员正在从「创造者」变成「监工」
## 二、代码之神已经诞生
## 三、独立开发者的终极困境
## 四、给想转码的人一个忠告
## 五、2026 年最值钱的技能组合
## 六、尾声
```

**第五.5步：去除 AI 味表达**

在保存元文章之前，使用 `humanizer-zh/` skill 对文章进行自然化处理，去除 AI 生成内容的典型特征。

**语言检测与 Skill 选择：**

| 内容语言 | 使用的 Skill               | 说明             |
| -------- | -------------------------- | ---------------- |
| **中文** | `humanizer-zh/SKILL.md`    | 中文内容去 AI 味 |
| **英文** | `humanizer-zh/SKILL-en.md` | 英文内容去 AI 味 |

**执行流程：**

1. **检测内容语言**：判断当前文章是中文还是英文
2. **调用对应 Skill**：

   ```bash
   # 中文内容
   humanizer-zh/

   # 英文内容
   humanizer-zh/-en
   ```

3. **应用优化建议**：根据 humanizer 的输出，修改以下常见 AI 味表达：
   - **过度使用连接词**：「首先...其次...最后...」「一方面...另一方面...」
   - **模板化开头**：「在当今社会...」「随着...的发展...」
   - **空洞的总结**：「综上所述」「总而言之」
   - **过度礼貌用语**：「让我们来看看...」「值得注意的是...」
   - **机械化列举**：过多的「此外」「另外」「同时」
4. **保持核心内容**：优化表达方式，但不改变文章的核心观点和论证逻辑
5. **用户确认**：展示优化后的内容，等待用户确认

**注意事项：**

- humanizer 处理是可选步骤，用户可以选择跳过
- 如果用户对当前内容满意，可直接进入下一步
- 多平台版本生成时，每个版本单独进行 humanizer 处理

### dankoe 变体生成流程（特殊流程）

当用户选择「dankoe 变体」时，执行以下特殊流程：

**与普通变体的区别：**

- 普通变体是对元文章进行格式转换或翻译
- dankoe 变体是根据元文章的**核心主题/输入内容**，使用 dankoe 人设**重新生成**一篇完整的英文长文（3000-6000 词）

**dankoe 变体生成步骤：**

**步骤 1：提取核心主题**

从元文章或用户输入中提取：

- 核心论点/观点
- 关键洞察
- 目标读者痛点
- 可借鉴的例子或数据

**步骤 2：战略重构（使用 dankoe 人设）**

读取 `brands/dankoe.md` 配置，按照 Dan Koe 风格设计文章：

1. **挑衅式开头**：一个挑战常规认知的断言
2. **个人故事/confession**：建立可信度
3. **系统框架**：将观点组织成可操作的步骤（3-7 步）
4. **游戏/系统隐喻**：将生活比作游戏、系统优化
5. **金句密度**：每 300-500 词一个可引用的金句
6. **行动号召**：明确的下一步指引

**步骤 3：生成完整英文长文**

- 目标字数：3000-6000 词（通常约 4000 词）
- 语言：英文
- 风格：短句为主、直接、自信、无 hedge words
- 禁止：em dash（使用逗号或句号代替）

**关键格式要求（详见 brands/dankoe.md）：**

- **段落结构**：单句段落为主，创造视觉节奏和冲击力
- **Punch 密度**：每 300-500 词需要一个"可截图"的金句
- **签名格式**：文章结尾使用 `-- James` 签名，后接随机 CTA
- **CTA 变体**：根据文章类型选择合适的 CTA（Follow/Engagement/Challenge 等）

**步骤 4：内容评估循环**

与原创模式相同，调用 `content-eval`（需独立安装） 进行评估：

- 使用 `dankoe` 品牌配置进行品牌一致性评估
- 综合评分 ≥ 9.0 才进入下一步
- 改写次数 ≥ 3 次仍未达标，通知用户人工干预

**步骤 5：生成封面图（版画风格）**

dankoe 变体的封面图必须：

1. 使用**版画风格**（engraving），不是素描
2. 将文章主题**转换为超现实/科幻/神秘场景**

**超现实场景转换流程：**

```
文章主题 → 识别核心概念 → 转换为视觉隐喻 → 版画风格提示词
```

**转换示例：**

| 文章核心主题       | 超现实视觉场景                                                                                           |
| ------------------ | -------------------------------------------------------------------------------------------------------- |
| 逃离传统职业道路   | A figure emerging from a cracked marble statue of a businessman, surrounded by floating geometric shapes |
| 技能叠加的复利效应 | A human climbing an impossible M.C. Escher-style staircase made of interconnected books and gears        |
| 信息过载时代的专注 | A lone figure in a small boat navigating through a sea of floating digital screens and symbols           |
| 打破社会默认设置   | A person standing before a giant control panel with levers labeled "default" being switched off          |

**版画风格封面图提示词模板：**

```
A highly detailed, monochrome engraving style illustration depicting [超现实场景描述].

The artwork is rendered strictly in binary black ink on aged white paper, resembling a vintage woodcut or scratchboard print. There are no grey tones, only pure black and white.

Shading, texture, and volume are expertly achieved through a combination of dense cross-hatching lines, intricate stippling (dot work), and swirling line patterns. Stark, high-contrast chiaroscuro lighting creates dramatic silhouettes and deep shadows. The overall atmosphere is gritty, serious, and textured, with an epic or surreal quality.

Aspect ratio: 3:1
```

**步骤 6：保存到 articles 目录**

dankoe 变体保存到 articles 目录（带子目录）：

```

├── dankoe-article.md              # dankoe 风格英文长文
├── prompts.json                   # 图片提示词
└── _attachments/
    └── cover-x.png       # 版画风格封面图 (3:1)
```

**步骤 7：发布到 X Articles**

当用户说「发布 dankoe 文章」时：

2. 调用 `发布工具/x-publisher/` skill 发布到 X Articles
3. 使用 @BuildWithJames 账号

2. **提供复制选项**：
   - 「复制纯文本」→ 仅复制文字内容
   - 「复制 Markdown」→ 复制带图片引用的 Markdown
   - 「复制 HTML」→ 复制可直接粘贴到富文本编辑器的 HTML

详见 `references/output-format.md` 中的输出规范。

**第十一.5步：镜头检查（读者中心验证）**

在预览确认后、生成传播素材前，执行镜头检查，确保内容以读者为中心。

**检测 Prompt：**

```
这篇内容不是关于我的。请逐段分析：哪些部分在解决读者的具体问题，哪些部分在展示我自己。给出比例，并把所有"展示我"的段落改写成"服务读者"的版本。
```

**执行流程：**

1. **逐段分析**：识别每段内容是「服务读者」还是「展示自己」
2. **计算比例**：统计两类内容的占比
3. **判断是否通过**：
   | 服务读者占比 | 操作 |
   |-------------|------|
   | ≥ 60% | ✅ 通过，进入下一步 |
   | < 60% | ⚠️ 改写「展示自己」的段落，重新检查 |

4. **改写原则**：
   - 「我们团队经过三个月调研...」→「您的问题可以在两周内解决...」
   - 「我完成了A项目...」→「A项目已锁定，下周可进开发...」
   - 「我们历时两年打磨...」→「你30秒内就能找到任何历史文件...」

**核心原则**：镜头朝自己 → 礼貌性点头；镜头朝对方 → 开始行动

**详见**：镜头理论已内联在本文件中（搜索"镜头理论"）

**第十二步：生成传播素材**

文章完成后，自动生成以下传播素材，**单独保存为 `promotion.md` 文件**（不添加到 article.md 正文）：

1. **文章摘要**（120 字以内）
   - 提炼文章核心观点
   - 保留最具冲击力的金句
   - 适用于：公众号摘要、文章简介、SEO 描述

2. **朋友圈分享文案**
   - 3-5 行，口语化
   - 引发好奇或共鸣
   - 可带 1-2 个话题标签
   - 以「→ 点击阅读全文」或类似引导语结尾

3. **LinkedIn 分享文案**（英文，150 字以内）
   - 用于 LinkedIn "Tell my network what your article is about"
   - 简洁概括文章核心观点
   - 专业但有吸引力的语气
   - 末尾包含不超过 5 个 hashtag
   - 适用于：LinkedIn 文章分享、动态发布

**文件保存位置：** `01-内容生产/选题管理/02-待发布/{日期}-{文章标题}/promotion.md`

### 素材重构模式流程

详见 `references/reconstruction.md`

**前置条件：** 品牌配置已在「第零步」确定。以下所有步骤都应遵循当前品牌配置（如有）的调性、语言风格和内容边界。

---

**🚨 抄袭陷阱警告（最高优先级）**

> **素材重构 ≠ 改写原文。素材重构 = 提取原理 + 全新展开。**

**禁止保留原文的：**
- ❌ 案例（必须100%替换）
- ❌ 结构（必须重新设计）
- ❌ 金句（必须重新创作）
- ❌ 历史引用/数据（必须换新的或删除）
- ❌ 众生相人物（必须全新设计）

**只能保留原文的：**
- ✅ 最抽象的核心原理（一句话）
- ✅ 底层洞察/认知框架

**检验标准：** 如果读者能看出你的文章出处是哪篇，就是失败。

---

**⚠️ 强制步骤：内容筛选（MANDATORY）**

**在开始素材解构前，必须先执行 `content-filter/` 进行内容筛选。**

这是**宪法级别的规则**，不可跳过。

**执行流程：**

1. **调用 content-filter skill**：
   ```
   content-filter/ [粘贴原文内容]
   ```

2. **根据筛选结果决策**：

   | 分类 | 受众适配度 | 操作 |
   |------|-----------|------|
   | **A类** | ≥70% | ✅ 继续素材重构流程 |
   | **B类** | 40-69% | ⚠️ 告知用户需大幅调整，询问是否继续 |
   | **C类** | <40% | ❌ 停止流程，建议放弃或换选题 |

3. **如果是 A 类或用户确认继续的 B 类**：
   - 记录平台适配建议（公众号/小红书/X）
   - 记录改写方向（场景替换/案例替换/保持不变）
   - 进入下一步：素材解构

**为什么这是强制步骤？**
- ❌ 避免浪费时间：C类文章不值得改写
- ✅ 提高质量：提前知道平台适配性和改写方向
- ✅ 提升效率：先筛选再重构，而不是反过来

---

**第一步：提取核心原理（只提取，不解构）**

> ⚠️ 这一步只做一件事：用一句话提取原文的核心原理。

**输出格式：**
```
核心原理（一句话）：_______________
```

**示例：**
- 原文讲震动棒被父母发现 → 核心原理：「父母的道德指责，本质是对失控的恐惧」
- 原文讲职场PUA → 核心原理：「权力不对等关系中，弱势方的自我怀疑是被设计的」

**禁止在这一步做的事：**
- ❌ 分析原文的张力场、众生相、金句（这些都不能用）
- ❌ 提取原文的结构骨架（结构要重新设计）
- ❌ 记录原文的案例细节（案例要100%替换）

---

**第二步：全新切入角度设计**

基于核心原理，设计3-5个**全新的切入角度**，让用户选择：

| 角度 | 切入点 | 与原文的区别 |
|------|--------|-------------|
| A | _______ | _______ |
| B | _______ | _______ |
| C | _______ | _______ |

**设计原则：**
- 每个角度都必须与原文完全不同
- 保留核心原理，但换一个全新的场景/人群/视角
- 优先选择有热点属性的角度

等待用户选择。

---

**第三步：战略输出（六轨并行）**

用户选择角度后，基于新角度进行战略输出：

**A. 张力共鸣法设计**（全新设计，不是迁移）

1. **新张力场角度**：必须与原文不同的对立视角
2. **全新众生相设计**：场景、人物、细节 100% 替换
3. **情绪扳机重设计**：新的断言，保留冲击力但换个说法
4. **时效性更新**：植入当下热点，替换原文过时元素

**B. 哲学武器库重部署**（维特根斯坦「语言游戏」核心）5. **意向性锚点转换**：用什么新的「某物」唤起注意力？6. **权力意志新表达**：同样的认知冲击，换一种激发方式7. **框架劫持迁移**：保留论证逻辑，换一套概念命名8. **镜像人物替换**：让不同的读者群体看到自己

**C. 结构重编** 9. **章节结构方案**：

- 判断：需要分章节 / 无需分章节
- 若需分章节：列出 3-6 个章节标题草案
- 若无需分章节：说明将用自然段落 + 金句组织
- 注明：与原文结构是否相同，为何选择这种结构

等待用户确认。

**第三步：执行重构**

按照重构策略，产出全新文章草稿。

**第四步：内容评估循环**

草稿完成后，自动进入评估-改写循环：

1. **调用评估**：使用 `content-eval`（需独立安装） skill 对草稿进行多维度评估
   - 如未安装 `content-eval`（需独立安装），提示用户安装：https://github.com/iamzifei/chinese-viral-editor
   - **使用当前品牌配置**：如有品牌配置，传入配置名称进行品牌一致性评估
   - 评估维度包括：张力场强度、情绪扳机效果、众生相穿透力、金句质量、品牌一致性（如有配置）
   - 特别检查：与原文的差异度（需 > 80%）

2. **根据评分决策**：
   | 综合评分 | 改写次数 | 操作 |
   |---------|---------|------|
   | ≥ 9.0 | - | ✓ 通知用户确认，进入下一步 |
   | < 9.0 | < 3 | → 根据评估反馈改写，返回评估 |
   | < 9.0 | ≥ 3 | ⚠ 通知用户进行人工评估和干预，用户确认后进入下一步 |

3. **改写策略**：根据评估输出的具体建议，针对性改进

4. **评估结果归档**：将每次评估的分数和反馈保存，用于 RLHF 学习

**第五步：RLHF 学习**

用户确认草稿后，将评估反馈纳入 RLHF 自进化系统。

**第六步：确定章节结构**

根据文章内容智能判断是否需要分章节：

| 条件                           | 结构选择   | 说明                         |
| ------------------------------ | ---------- | ---------------------------- |
| 字数 ≤ 1000 且 核心观点 ≤ 2 个 | **无章节** | 用自然段落 + 加粗金句组织    |
| 字数 > 1000 或 核心观点 ≥ 3 个 | **有章节** | 使用 `## 一、二、三...` 标题 |

**注意：** 重构后的章节结构不必与原文相同。根据新的张力场和观点数量重新决定是否分章节，以及如何划分。

章节标题撰写规范同原创模式。

**第六.5步：去除 AI 味表达**

同原创模式第五.5步，使用 `humanizer-zh/` skill 对文章进行自然化处理：

1. **检测内容语言**：判断当前文章是中文还是英文
2. **调用对应 Skill**：
   - 中文内容：`humanizer-zh/`
   - 英文内容：`humanizer-zh/`（英文模式）
3. **应用优化建议**：去除 AI 味表达（详见原创模式第五.5步）
4. **用户确认**：展示优化后的内容

**第七步：保存元文章**

草稿定稿后，**首先**将元文章保存到 `articles/` 目录：

```
01-内容生产/选题管理/02-待发布/{YYYY-MM-DD}-{文章标题}.md
```

**元文章特点：**

- 纯文本内容，不包含配图引用
- 作为创作源文件存档
- 用于 RLHF 历史文章导入和回溯

**第八步：生成图片提示词文件（prompts.json）**

元文章保存后，首先生成图片提示词文件：

```

```

**prompts.json 结构：** 同原创模式第七步。

**图片类型及提示词模板：**

1. **封面图**（铅笔素描风格）：为每个平台生成对应比例的封面图
2. **章节插图**（黑白漫画手稿风格）：为每个章节生成 4:3 横版插图
3. **信息图**（手绘卡通风格）：如果文章包含数据、概念关系或流程，生成 4:3 横版信息图

**第九步：配图处理（提示词优先）**

只有当用户明确要求「自动生成图片」时，才执行：

```bash
python scripts/generate_images.py 01-内容生产/选题管理/02-待发布/{YYYY-MM-DD}-{文章标题}/prompts.json
```

图片保存到 `01-内容生产/选题管理/02-待发布/{YYYY-MM-DD}-{文章标题}/_attachments/` 目录。

**第十步：选择平台和变体**

配图生成后，向用户展示平台选择界面（同原创模式），**必须等待用户明确选择**。

**⚠️ 无默认选项，必须询问用户确认。**

**平台选项：**

| 选项           | 包含平台                                | 说明                                         |
| -------------- | --------------------------------------- | -------------------------------------------- |

| **仅微信**     | 微信公众号                              | 只发布到微信                                 |
| **仅小红书**   | 小红书长文 + 小红书短文                 | 只发布到小红书（两种版本）                   |

   - 末尾包含不超过 5 个 hashtag
   - 适用于：LinkedIn 文章分享、动态发布

**Roland 在不同平台有不同的人设，生成内容时必须遵守：**

   - 核心论点和底层原理保持一致
   - 表层场景和人物完全不同

**第七步：小红书长文版本处理（xhs-long.md）**

将元文章改写为小红书图文帖格式。

**文件格式：**

- Markdown 格式（`.md`）
- 包含：H1 标题、图片引用、正文内容、hashtags
- 内容长度不超过 900 字符（不含标题、图片引用和标签）
- 标签数不超过 5 个

**格式模板：**

```markdown
# {标题，约20字符}

![](./_attachments/xhs-01.png)
![](./_attachments/xhs-02.png)

{正文内容，不超过900字符}

{可适当使用表情符号和分段}

#标签1 #标签2 #标签3 #标签4 #标签5
```

**格式规范：**

| 元素 | 要求                                        |
| ---- | ------------------------------------------- |
| 标题 | H1 格式，建议约 20 字符，吸引眼球           |
| 图片 | 引用 `./_attachments/` 目录下的图片，可多张 |
| 正文 | 不超过 900 字符，口语化、轻松               |
| 标签 | 最多 5 个，末尾放置，空格分隔               |

**改写原则：**

1. **标题吸睛**：约 20 字符，直击痛点或引发好奇
2. **内容精炼**：不超过 900 字符，保留核心观点和金句
3. **口语化**：比原文更加口语化、轻松，像跟朋友聊天
4. **分段清晰**：每段 2-4 行，便于手机阅读
5. **金句突出**：保留最有冲击力的 1-2 句金句
6. **收获感**：用通俗易懂的语言让普通人有收获

**图片引用说明：**

- 图片应放在 `./_attachments/` 目录下
- 使用相对路径引用
- 可引用多张图片，发布时按顺序展示
- 如无自定义图片，可使用生成的 `cover-xhs.png`

**示例：**

```markdown
# 周末好去处

![](./_attachments/xhs-01.png)
![](./_attachments/xhs-02.png)

发现了一家超赞的咖啡店，环境特别好！

推荐指数：⭐⭐⭐⭐⭐

#咖啡 #探店 #周末
```

**表情符号使用原则：**

- 可在重点句后适当使用
- 不要过度使用，保持专业感
- 常用：💡 ✨ 🔥 📌 ⭐ 🎯 💪 🤔

**第八步：小红书短文版本处理（xhs-short.txt）**

将元文章精简为 ≤500 字的小红书短文版本。

**文件格式：**

- 纯文本格式（`.txt`）
- 只包含：文字内容、换行、分段、列表
- 末尾添加不超过 5 个相关 hashtag

**改写原则：**

- 精简核心观点，去除次要内容
- 更加口语化、轻松
- 保留最有冲击力的金句
- 开头要能抓住注意力

## RLHF 自进化系统

详见 `references/rlhf-loop.md`

### 自动化管理脚本

使用 `scripts/rlhf_manager.py` 自动管理 RLHF 循环：

```bash
# 首次使用：初始化规则库
python scripts/rlhf_manager.py init

# 查看帮助
python scripts/rlhf_manager.py --help
```

### 进化循环

每次创作自动执行：

**Phase 1: Generate（开始创作）**

```bash
# 开始新 episode，自动选择本次应用的规则
python scripts/rlhf_manager.py start-episode --mode 原创 --topic "文章主题"

# 查看本次应用的规则（JSON 格式）
python scripts/rlhf_manager.py apply-rules
```

**Phase 2: Feedback（记录反馈）**

```bash
# 记录用户对特定规则的反馈
# signal 值: 1.0=表扬, 0.5=采用, 0.0=小改, -0.5=大改, -1.0=批评
python scripts/rlhf_manager.py record-feedback rule_001 1.0 --comment "金句很好"

# 记录一次修改
python scripts/rlhf_manager.py record-revision
```

**Phase 3-4: Reward + Update（完成并更新得分）**

```bash
# 完成当前 episode，自动计算规则得分
python scripts/rlhf_manager.py complete-episode

# 如果用户不采用，标记为拒绝
python scripts/rlhf_manager.py complete-episode --rejected
```

**Phase 5: Consolidate（整合规则）**

```bash
# 每 10 次自动提醒，也可手动执行
python scripts/rlhf_manager.py consolidate
```

### 完整工作流示例

```bash
# 1. 开始创作
python scripts/rlhf_manager.py start-episode --mode 原创 --topic "AI焦虑"

# 2. Claude 根据规则生成文章...
```

### 规则得分机制

**反馈信号映射：**
| 反馈 | 信号值 | 含义 |
|-----|-------|------|
| 明确表扬 | +1.0 | 「这里好」「金句很棒」 |
| 无修改采用 | +0.5 | 直接发布，无修改 |
| 小修改 | +0.0 | 修改 1-2 轮 |
| 大幅修改 | -0.5 | 修改 3+ 轮 |
| 明确批评 | -1.0 | 「这里不行」「太平了」 |

**规则得分计算：**

```
得分 = (Σ 反馈信号 + 1) / 2  # 归一化到 0-1
置信度 = 1 - 1/(应用次数 + 1)
```

**规则策略：**
| 得分 | 置信度 | 操作 |
|-----|-------|------|
| > 0.7 | > 80% | 强化：优先应用 |
| 0.3-0.7 | > 80% | 保持：继续观察 |
| < 0.3 | > 80% | 弱化：考虑淘汰 |
| 任意 | < 50% | 探索：增加应用 |

读者读完应有以下反应之一：

1. 「说得太对了，转发」
2. 「这说的就是我」
3. 「胡说八道，我要反驳」
4. 「这个观点有意思」

四种反应都产生互动。没有反应才是失败。
