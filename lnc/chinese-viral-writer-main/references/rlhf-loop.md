# RLHF Loop 自进化系统

## 核心理念

传统的反馈记录是「被动收集」，RLHF Loop 是「主动进化」。

区别在于：
- 被动收集：用户说什么记什么，规则堆积
- 主动进化：系统自己归纳、测试、优化、淘汰规则

## 五阶段循环

### Phase 1: Generate（生成）

基于当前规则集生成内容。

**输入：** 主题/素材 + 当前规则集
**输出：** 文章 + 元数据（使用了哪些规则）

**关键：** 记录本次生成应用了哪些规则，便于后续归因。

### Phase 2: Feedback（反馈收集）

收集用户的显式和隐式反馈。

**显式反馈：**
- 「这里好」「这里不好」
- 「改成这样」
- 评分（如果用户愿意给）

**隐式反馈：**
- 用户是否要求修改？（无修改 = 正向信号）
- 修改了几轮？（轮次越少越好）
- 用户最终是否采用？

**关键：** 主动询问结构化反馈。

### Phase 3: Reward Modeling（奖励建模）

将反馈转化为规则的「得分」。

**规则得分计算：**
```
规则得分 = Σ(应用次数 × 反馈信号) / 应用总次数

反馈信号：
  +1.0 = 明确表扬
  +0.5 = 无修改直接采用
  +0.0 = 有小修改
  -0.5 = 大幅修改
  -1.0 = 明确批评
```

**规则置信度：**
```
置信度 = 1 - 1/(应用次数 + 1)

应用 1 次：置信度 50%
应用 5 次：置信度 83%
应用 10 次：置信度 91%
```

### Phase 4: Update（策略更新）

根据得分更新规则集。

**规则突变策略：**

| 得分区间 | 置信度 | 操作 |
|---------|-------|------|
| > 0.7 | > 80% | 强化：提升优先级，考虑泛化 |
| 0.3 ~ 0.7 | > 80% | 保持：继续观察 |
| < 0.3 | > 80% | 弱化：降低优先级，考虑淘汰 |
| 任意 | < 50% | 探索：增加应用机会以收集数据 |

**规则泛化：**
当一个具体规则得分高时，尝试提取更抽象的规则。

示例：
- 具体规则：「用程序员的例子效果好」
- 泛化规则：「用互联网行业的例子效果好」
- 再泛化：「用读者熟悉的行业例子效果好」

**规则特化：**
当一个抽象规则在某些场景失效时，拆分为条件规则。

示例：
- 原规则：「金句要狠」
- 特化后：「职场话题金句要狠，情感话题金句要扎心但不要刻薄」

### Phase 5: Consolidate（整合优化）

定期（每 10 次创作或用户主动触发）进行规则整合。

**整合操作：**

1. **去重合并** - 合并语义相似的规则
2. **冲突解决** - 发现矛盾规则，保留高分规则
3. **层级整理** - 将规则组织成树状结构
4. **死规则清理** - 删除长期未使用或持续低分的规则
5. **过拟合检测** - 识别过于具体、不可泛化的规则

## 实现指令

### 每次创作时

```markdown
1. 读取规则文件
2. 选择本次应用的规则（优先选高分高置信规则）
3. 生成内容
4. 记录本次应用的规则 ID
5. 收集反馈
6. 更新规则得分
7. 检查是否触发整合（每 10 次）
```

### 主动探索机制

为避免陷入局部最优，每 5 次创作进行一次「探索」：

- 随机选择一个低置信度规则强制应用
- 或尝试一个新的变体规则
- 记录探索结果

### A/B 测试机制

当用户时间允许时，可以启用 A/B 测试：

```markdown
用户：帮我写一篇关于 XXX 的文章

Claude：我准备了两个版本：

**版本 A**（应用规则：狠金句 + 跳跃结构）
[内容]

**版本 B**（应用规则：温和金句 + 线性结构）
[内容]

你更喜欢哪个？这会帮助我优化规则。
```

## 自进化触发词

用户可以通过以下方式主动触发进化操作：

| 触发词 | 操作 |
|-------|------|
| 「进化报告」 | 输出当前规则集状态和得分 |
| 「整合规则」 | 立即执行 Consolidate |
| 「A/B 测试」 | 下次创作启用双版本 |
| 「探索模式」 | 下次创作尝试低置信规则 |
| 「重置规则」 | 清空学习记录，回到初始状态 |
| 「导出规则」 | 输出可迁移的规则文件 |

## 进化报告示例

```markdown
## 📊 Skill 进化报告

**总创作次数：** 23 次
**平均修改轮次：** 1.3 轮
**采用率：** 87%

### 高分规则 TOP 5
1. [0.92] 金句要狠，能截图发朋友圈
2. [0.88] 例子用互联网行业
3. [0.85] 开头不用问句
4. [0.82] 众生相要有「打工人」
5. [0.80] 结尾留悬念不要说教

### 低分规则（待淘汰）
1. [0.25] 每段都要有转折 ← 建议删除
2. [0.30] 用历史典故 ← 建议降级

### 待验证规则（低置信度）
1. [?] 标题用数字效果好（仅应用 2 次）
2. [?] 负面情绪比正面更易传播（仅应用 1 次）

### 建议操作
- 删除规则 #12（得分 0.25，置信度 85%）
- 合并规则 #3 和 #7（语义重复）
- 对规则 #15 进行 A/B 测试验证
```

## 冷启动策略

新用户没有历史数据时：

1. 使用默认规则集（来自 methodology.md 和 style-rules.md）
2. 前 5 次创作强制收集结构化反馈
3. 第 5 次后启用完整 RLHF Loop
