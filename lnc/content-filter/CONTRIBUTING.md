# 贡献指南 / Contributing Guide

感谢你对本项目的兴趣！我们欢迎各种形式的贡献。

## 如何贡献

### 报告问题 / Report Issues

如果你发现了 bug 或有功能建议：

1. 先搜索现有 Issues，避免重复
2. 创建新 Issue，清楚描述问题或建议
3. 如果是 bug，请提供复现步骤

### 提交代码 / Submit Code

1. Fork 本仓库
2. 创建你的特性分支 (`git checkout -b feature/AmazingFeature`)
3. 提交你的更改 (`git commit -m 'Add some AmazingFeature'`)
4. 推送到分支 (`git push origin feature/AmazingFeature`)
5. 创建 Pull Request

### 贡献方向

#### 1. 平台规则更新

各平台的规则和算法经常变化，欢迎补充最新的：
- 平台内容政策变化
- 算法推荐机制更新
- 新的内容形式支持

编辑位置：`skill/content-evaluation.md` 中的「平台匹配度」部分

#### 2. 添加新平台支持

添加新平台时，请提供：
- 平台基本信息（用户群体、内容调性）
- 内容格式建议（长度、标签、格式）
- 算法偏好说明
- 合规红线清单

添加位置：
- `skill/content-evaluation.md` - 更新平台特征速查表
- `docs/platform-guides/` - 添加新平台详细指南

#### 3. 优化评估维度

如果你有专业背景，欢迎优化：
- 评估标准和评分细则
- 权重配置建议
- 行业特定的评估模板

#### 4. 改进学习模块

贡献学习模块的改进：
- 更好的数据关联算法
- 新的学习指标
- 优化校准建议逻辑

#### 5. 文档和示例

- 补充使用示例
- 改进文档清晰度
- 翻译为其他语言

## 代码规范

### Markdown 文件

- 使用清晰的标题层级
- 表格对齐整齐
- 代码块标注语言类型

### 提交信息

使用清晰的提交信息：

```
feat: 添加抖音平台评估规则
fix: 修复事实核查评分逻辑
docs: 更新小红书平台指南
refactor: 重构决策架构部分
```

## 行为准则

- 尊重所有贡献者
- 提供建设性反馈
- 专注于改进项目

## 问题？

如有任何问题，请在 Issues 中提问。

再次感谢你的贡献！
