# 强制规则：系统自我迭代

**优先级**：最高
**触发条件**：发现重复问题、模式、或改进机会

---

## 迭代理念

> 系统不是静态的，而是随使用不断进化的。
>
> 每次使用都是学习机会，每次改进都沉淀为系统能力。

---

## 三层迭代机制

```
使用过程
    ↓
发现问题/模式
    ↓
├─→ 操作层迭代（单次改进）
│       └─ 立即执行，优化当前任务
│
├─→ 方法层迭代（知识沉淀）
│       └─ 记录到语义记忆，形成方法论
│           ↓
│       记忆库/语义记忆/我的XXX方法.md
│
└─→ 系统层迭代（规则固化）
        └─ 提炼为强制规则，自动化执行
            ↓
        记忆库/强制规则/强制规则_XXX.md
```

---

## 迭代触发条件

### 必须迭代的信号

| 信号 | 示例 | 迭代动作 |
|------|------|----------|
| **同一问题重复 3 次** | 总是忘记在任务中标注优先级 | 创建规则：任务必须包含优先级 |
| **手动操作繁琐** | 每次都要手动复制粘贴模板 | 创建 Skill：自动生成模板 |
| **决策困难反复** | 不确定内容该放哪个分类 | 创建规则：明确分类标准 |
| **输出质量不稳定** | 有时好有时差 | 创建规则：阶段门检查 |
| **用户反复纠正** | 多次提醒"中英之间加空格" | 创建规则：排版规范 |

### 迭代识别检查清单

每次对话结束时，自检：

- [ ] 本次对话中，用户纠正了我什么？
- [ ] 本次任务中，我重复执行了什么操作？
- [ ] 本次输出中，有什么可以标准化的？
- [ ] 本次决策中，有什么可以自动化的？

如果任意一项为「是」，触发迭代流程。

## 迭代流程

### 第 1 步：问题识别

```
发现问题
    ↓
记录：
- 问题描述
- 发生频率
- 影响范围
- 临时解决方案（如有）
```

### 第 2 步：模式提炼

```
分析问题
    ↓
提炼：
- 根本原因
- 通用模式
- 可复用解决方案
- 适用场景
```

### 第 3 步：层级决策

```
解决方案
    ↓
判断层级：
    ├─ 单次使用 → 操作层（立即执行）
    ├─ 可复用方法 → 方法层（语义记忆）
    └─ 必须自动执行 → 系统层（强制规则）
```

### 第 4 步：文档化

**方法层**：创建语义记忆文档

```markdown
# 我的XXX方法

## 问题背景
描述遇到的问题

## 解决方案
具体解决方法

## 使用场景
什么时候使用

## 示例
具体例子

## 效果评估
如何衡量效果
```

**系统层**：创建强制规则

```markdown
# 强制规则：XXX

## 触发条件
什么时候执行

## 必须执行
具体规则内容

## 禁止行为
什么不能做

## 检查清单
如何验证执行
```

### 第 5 步：验证与优化

```
应用新规则/方法
    ↓
观察效果
    ↓
├─ 有效 → 继续使用，定期回顾
└─ 无效 → 返回第 2 步，重新提炼
```

## 迭代示例

### 示例 1：从反复纠正到自动执行

**问题识别**：
- 用户多次提醒："中英之间要加空格"
- 发生频率：每次输出都出现
- 影响：降低专业感，增加校对时间

**模式提炼**：
- 根本原因：没有统一的排版标准
- 通用模式：中文排版有明确规范
- 解决方案：制定规则，强制执行

**层级决策**：必须自动执行 → 系统层

**文档化**：创建 `00-typography.md`

```markdown
# 中文文案排版规范

## 空格规则
1. 中英文之间必须加空格
2. 中文与数字之间必须加空格
3. 数字与单位之间不加空格
```

**效果**：
- 迭代前：每次输出都需要用户校对
- 迭代后：自动执行，零提醒

---

### 示例 2：从重复操作到 Skill

**问题识别**：
- 每次内容创作都要手动创建目录结构
- 手动复制模板文件
- 手动命名文件夹

**模式提炼**：
- 根本原因：缺乏自动化工具
- 通用模式：内容创作有固定格式
- 解决方案：封装为 Skill，一键执行

**层级决策**：可复用方法 → 方法层 + Skill

**文档化**：
1. 创建 `记忆库/语义记忆/内容创作流程.md`
2. 创建 `.claude/skills/content-creator/SKILL.md`

**效果**：
- 迭代前：每次创作花费 5 分钟准备
- 迭代后：一句话启动，自动完成准备

---

### 示例 3：从决策困难到分类标准

**问题识别**：
- 用户多次问："这个内容该放哪？"
- AI 也经常不确定分类
- 反复讨论分类问题

**模式提炼**：
- 根本原因：分类标准模糊
- 通用模式：内容有明确属性
- 解决方案：制定明确分类标准

**层级决策**：必须自动执行 → 系统层

**文档化**：创建 `强制规则_内容分诊.md`

```markdown
# 强制规则：内容分诊

## 6 个分类方向
1. 内容生产：可发布的素材
2. 项目：业务/工作相关资料
3. 学习：学习资料、研究
4. 个人成长：思考、灵感
5. 稍后处理：暂时无法分类
6. 归档：无需处理

## 判断标准
（详细标准见原文档）
```

**效果**：
- 迭代前：每次分诊都要讨论
- 迭代后：自动分类，用户确认即可

## 迭代回顾机制

### 每周回顾

```markdown
# 周迭代回顾

## 本周使用统计
- 对话次数：X
- 任务完成：Y
- 内容创作：Z

## 本周发现的问题
1. 问题 A：发生 3 次，已创建规则
2. 问题 B：发生 2 次，观察中

## 本周创建的改进
- 新增规则：X
- 新增方法：Y
- 新增 Skill：Z

## 下周迭代目标
- 优化 XXX 流程
- 创建 XXX Skill
```

### 每月回顾

```markdown
# 月迭代回顾

## 系统进化概览
- 规则数量：X → Y
- 方法数量：A → B
- Skill 数量：C → D

## 效率提升
- 任务处理时间：X% 提升
- 内容创作时间：Y% 提升
- 决策时间：Z% 提升

## 下月迭代方向
- 重点优化领域
- 计划创建的 Skills
```

## 迭代原则

### 1. 渐进式迭代

> 不要试图一次性完善所有规则。
> 从最常遇到的问题开始，逐步积累。

### 2. 用户主导

> AI 提出建议，用户决定是否迭代。
> 迭代方向必须符合用户实际需求。

### 3. 可逆性

> 所有迭代都可以回滚。
> 保留历史版本，随时可以恢复。

### 4. 效果验证

> 迭代后必须验证效果。
> 无效的迭代及时撤销或修正。

| 场景 | 用户指令 | AI 动作 |
|------|---------|---------|
| 发现规则需要改进 | "把这个规则记下来" | 创建/更新规则文件 |
| 总结方法论 | "把这个方法沉淀下来" | 创建语义记忆文档 |
| 封装重复操作 | "把这个做成 Skill" | 创建 Skill 文件 |
| 回顾迭代 | "本周有哪些改进？" | 输出迭代回顾 |
