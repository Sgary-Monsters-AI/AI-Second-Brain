# 备份与同步指南

确保你的 AI 管理系统数据安全，随时随地可用。

---

## 为什么需要备份

**数据价值**：
- 任务记录：时间管理和承诺追踪
- 内容创作：知识资产和创作成果
- 对话历史：决策过程和重要信息
- 系统配置：个性化规则和偏好

**风险场景**：
- 电脑损坏或丢失
- 误操作删除文件
- 软件故障导致数据损坏
- 需要在新设备上使用

---

## 备份方案对比

| 方案 | 优点 | 缺点 | 推荐度 |
|------|------|------|--------|
| **Git + GitHub** | 版本控制、历史回溯、免费 | 需要学习 Git | ⭐⭐⭐⭐⭐ |

| **本地硬盘** | 完全可控、速度快 | 单点故障风险 | ⭐⭐ |

## 方案 1：Git + GitHub（推荐）

### 为什么推荐 Git

```
时间线：
今天 ──→ 昨天 ──→ 上周 ──→ 上月
  ↑        ↑        ↑        ↑
最新    可回溯   可回溯   可回溯

误删？→ 一键恢复
改错？→ 回滚版本
对比？→ 查看差异
```

### 设置步骤

**1. 初始化 Git 仓库**

```bash
cd ~/AI-Admin-System

# 初始化
git init

# 配置用户信息（只需一次）
git config user.name "你的名字"
git config user.email "your@email.com"
```

**2. 创建 .gitignore**

```bash
# 创建忽略文件
cat > .gitignore << 'EOF'
# 系统文件
.DS_Store
Thumbs.db

# 临时文件
*.tmp
*.temp
*.log

# 大文件
*.zip
*.mp4
*.mov

# 私有配置（可选）
config.local.yml
.env
EOF
```

**3. 首次提交**

```bash
# 添加所有文件
git add .

# 提交
git commit -m "init: AI 管理系统系统初始化"
```

**4. 推送到 GitHub**

```bash
# 在 GitHub 创建仓库（网页操作）
# 获取仓库地址：https://github.com/username/repo.git

# 添加远程仓库
git remote add origin https://github.com/username/repo.git

# 推送
git push -u origin main
```

### 日常备份流程

```bash
# 每天结束时执行
cd ~/AI-Admin-System

git add .
git commit -m "backup: $(date +%Y-%m-%d)"
git push
```

### 自动备份脚本

创建 `backup.sh`：

```bash
#!/bin/bash
# AI 管理系统自动备份脚本

REPO_DIR="$HOME/AI-Admin-System"
LOG_FILE="$REPO_DIR/.backup.log"

cd "$REPO_DIR" || exit 1

# 检查是否有变更
if git diff --quiet && git diff --staged --quiet; then
    echo "$(date): 没有变更，跳过备份" >> "$LOG_FILE"
    exit 0
fi

# 添加、提交、推送
git add .
git commit -m "auto backup: $(date +%Y-%m-%d-%H:%M)" > /dev/null 2>&1
git push > /dev/null 2>&1

if [ $? -eq 0 ]; then
    echo "$(date): 备份成功" >> "$LOG_FILE"
else
    echo "$(date): 备份失败" >> "$LOG_FILE"
fi
```

设置定时任务：

```bash
# 给脚本执行权限
chmod +x ~/AI-Admin-System/backup.sh

# 编辑 crontab
crontab -e

# 添加以下行（每 3 小时备份一次）
0 */3 * * * /Users/$USER/AI-Admin-System/backup.sh

# 或每天 18:00 备份一次
0 18 * * * /Users/$USER/AI-Admin-System/backup.sh
```

## 方案 2：iCloud 同步（macOS）

### 设置步骤

**1. 移动目录到 iCloud**

```bash
# 关闭 iCloud 桌面与文稿（如果开启）
# 系统设置 → Apple ID → iCloud → 关闭"桌面与文稿"

# 移动目录
mv ~/AI-Admin-System \
   ~/Library/Mobile\ Documents/com~apple~CloudDocs/
```

**2. 创建软链接**

```bash
# 创建链接，保持原路径可用
ln -s ~/Library/Mobile\ Documents/com~apple~CloudDocs/AI-Admin-System \
      ~/AI-Admin-System
```

**3. 验证同步**

```bash
# 检查 iCloud 状态
ls -la ~/Library/Mobile\ Documents/com~apple~CloudDocs/

# 应该看到 AI-Admin-System 目录
```

### 注意事项

- iCloud 同步可能有延迟
- 大文件（>100MB）可能不同步
- 需要保持足够的 iCloud 空间

## 恢复数据

### 场景 1：误删文件

**Git 恢复**：
```bash
cd ~/AI-Admin-System

# 查看历史
git log --oneline

# 恢复特定文件
git checkout HEAD~1 -- 文件路径

# 恢复到最新提交（撤销未提交的删除）
git checkout HEAD -- 文件路径
```

**从归档恢复**：
```bash
# 检查归档目录
ls _Archive/

# 移动回原位
mv _Archive/文件名.md 原位置/
```

### 场景 2：恢复到历史版本

```bash
# 查看提交历史
git log --oneline

# 查看特定版本
git show abc123:文件路径

# 恢复到特定版本
git checkout abc123 -- .

# 或创建分支保留当前状态
git checkout -b backup-branch
git checkout main
git reset --hard abc123
```

### 场景 3：新设备恢复

```bash
# 克隆仓库到新设备
git clone https://github.com/username/repo.git ~/AI-Admin-System

# 安装 Claude Code
npm install -g @anthropic-ai/claude-code

# 启动使用
cd ~/AI-Admin-System
claude
```

## 多端同步策略

### 策略 1：Git 为主

```
电脑 A ──push──→ GitHub ──pull──→ 电脑 B
   ↑                                  ↓
   └──────────── sync ←───────────────┘
```

**工作流程**：
1. 工作前：`git pull` 获取最新
2. 工作中：正常使用
3. 工作后：`git add . && git commit -m "..." && git push`

### 策略 2：云同步 + Git

```
本地目录 ──sync──→ iCloud/Dropbox
    ↓
Git 版本控制（可选）
```

**适用场景**：单用户多设备

### 策略 3：纯云同步

**不推荐**，因为没有版本控制，误删无法恢复。

## 灾难恢复计划

### 最坏情况：电脑完全损坏

**恢复步骤**：

1. **新电脑安装**
   ```bash
   # 安装 Node.js
   # 安装 Claude Code
   npm install -g @anthropic-ai/claude-code
   ```

2. **恢复数据**
   ```bash
   # 从 GitHub 克隆
   git clone https://github.com/username/repo.git ~/AI-Admin-System

   # 或从云盘恢复
   # 登录 iCloud/Dropbox，等待同步完成
   ```

3. **验证完整性**
   ```bash
   cd ~/AI-Admin-System
   ls -la  # 检查文件是否完整
   ```

4. **恢复使用**
   ```bash
   claude
   启动 AI 助手
   ```

**预计恢复时间**：10-30 分钟

## 最佳实践

1. **321 原则**
   - 3 份备份
   - 2 种不同介质
   - 1 份异地存储

2. **定期测试恢复**
   - 每季度测试一次恢复流程
   - 确保备份真的可用

3. **重要变更立即备份**
   - 完成重要任务后立即提交
   - 不要等待定时备份

4. **记录备份状态**
   ```bash
   # 查看备份状态
   git log --oneline -10

   # 查看最后备份时间
   ls -la .backup.log
   ```
